全流程 Stage 总览

后端（物理实现）流程通常分为 9 个 stage（#0–#8）。每个 stage 有明确的输入、产出 checkpoint 与进入下一阶段的 gate。 工业界常把 #0/#1/#2/#3 在工具里连续执行，但它们的判据互相独立，建模时建议分清。
RC 抽取 / SPEF 是贯穿 post-route 与 signoff 的横切动作（timing 准不准的前提），在下表中归入 #7。
#Stage一句话职责关键产出 / 出口 gate
0Design Import
数据准备		读入网表/约束/库，配置 MMMC，globalNetConnect库约束零 error、时钟全定义
1Floorplan
布局规划		定 die/core、摆 IO pin/pad、macro 摆放、blockage初始 DEF、面积冻结、macro 无重叠
2Power Planning
电源规划		电源环/条带、sroute、tap/decap/switchPG 连通、static IR drop 达标
3Placement
标准单元布局		std cell 布局 + pre-CTS 优化、scan reorder、tie cell合法布局、congestion 可接受、pre-CTS timing
4CTS
时钟树综合		时钟树构建、skew 平衡、clock 布线、useful skewskew/insertion delay 达标、post-CTS timing

各 Stage 的 AI 辅助 / 自动化难度

用于判断 agent 应在哪些 stage 全自动推进，哪些 stage 需停下来请人确认。

#Stage可脚本化程度人类判断权重适合 AI 自动跑？
0Design Import高低✅ 全自动
1Floorplan (macro/pin)低高⚠️ 辅助为主，人定 macro/pin
2Power Planning中-高中✅ 模板化，参数可调
3Placement高中✅ 自动 + 人看 congestion
4CTS中-高中✅ 自动 + 人定 spec
5Routing高低-中✅ 自动，人看 DRC 收敛
6Timing ECO中高⚠️ 自动跑 + 人定策略
7Signoff中高⚠️ 自动跑工具，人判 waiver
8Tapeout高高❌ 人工把关
结论：macro/pin 摆放（#1）和 timing ECO（#6）是判断权重最高的两段，agent 应在这两处显式停下来请人确认； 其余高可脚本化的 stage 适合 agent 自动推进，人只看关键报告（congestion / DRC / timing）。
Skill 化提示：详细表中 ✅ 机械 的步骤坍缩成两个横切 skill 家族—— 知识类（已有 search-eda-command 等）与动作类（缺 parse-eda-report + run-eda-script，价值最大）。

对照本系统当前建模

本系统 orchestrator 目前把 9 个工业 stage 精简为 3 个流水线 stage + 2 个特殊角色。

本系统类型覆盖的工业 stage备注
spec人工审批阶段—SPEC_REVIEW，不在 stages 流水线里
floorplan流水线 stage#0 Import + #1 Floorplan + #2 Power + #3 Placement偏粗 4 步合并
cts流水线 stage#4 CTS—
route流水线 stage#5 Routing—
timing-eco按需 agent#6 Timing Closure可在任意 stage 后派发
缺—#7 Signoff（含 RC 抽取/SPEF）termination_criteria 已声明但无对应 stage
缺—#8 Tapeout可能有意排除在自动流程外
两点建议：
① 把 placement 从 floorplan 拆出来做独立 stage——它有自己的 gate（congestion、pre-CTS timing），失败时可独立 retry 而不连累 macro 摆放。
② 补一个 signoff stage（含 RC 抽取/SPEF），让 termination_criteria 里的 timing/DRC 目标有真正的 gate 守着。
建议目标流水线：floorplan → placement → cts → route → signoff。
