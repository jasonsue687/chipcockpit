# Search EDA Command

Retrieve structured documentation for a specific Tcl command from a preprocessed EDA tool User Guide. This skill reads from `knowledge/processed_eda/<tool_name>.json` — a structured database generated offline by `parsers/pdf_to_structured.py`.

## When to Use This Skill

Use this skill when the user needs:
- Syntax and arguments for a specific Tcl command
- Description of what a command does in a specific EDA tool
- Examples of command usage
- To discover similar commands when an exact name is unknown

## Required Inputs

Identify these two parameters from the user's request:
- **`tool_name`**: The EDA tool name (e.g., `innovus`, `genus`, `tempus`). Map common variants:
  - "Innovus", "innovus", "iNovus" → `innovus`
  - "Genus", "genus" → `genus`
  - "Tempus", "tempus" → `tempus`
- **`command_name`**: The Tcl command to look up (e.g., `place_opt`, `route_opt`, `report_timing`)

If either is missing, ask the user before proceeding.

## How to Execute

### Step 1: Locate the JSON database

Construct path:
```
$CLAUDE_PLUGIN_ROOT/knowledge/processed_eda/<tool_name>.json
```

Use the Read tool to load the file.

### Step 2: Search for the command

Parse the JSON array. Each entry has this schema:
```json
{
  "command": "place_opt",
  "description": "Performs global placement and optimization.",
  "syntax": "place_opt [-effort <low|medium|high>] [-congestion]",
  "arguments": [
    {"name": "-effort", "type": "string", "values": ["low", "medium", "high"], "description": "Controls optimization effort level."},
    {"name": "-congestion", "type": "flag", "description": "Enables congestion-driven placement."}
  ],
  "examples": ["place_opt -effort high", "place_opt -congestion -effort medium"]
}
```

**Search logic (in order):**
1. **Exact match**: `entry["command"] == command_name` (case-insensitive)
2. **Prefix match** (if no exact match): collect all entries where `entry["command"].startswith(command_name)` or `command_name.startswith(entry["command"])`

### Step 3: Return results

**If exact match found**, return the full structured entry:

```
## Command: place_opt (innovus)

**Description**: Performs global placement and optimization.

**Syntax**:
\`\`\`tcl
place_opt [-effort <low|medium|high>] [-congestion]
\`\`\`

**Arguments**:
| Argument | Type | Values | Description |
|----------|------|--------|-------------|
| -effort | string | low, medium, high | Controls optimization effort level. |
| -congestion | flag | — | Enables congestion-driven placement. |

**Examples**:
\`\`\`tcl
place_opt -effort high
place_opt -congestion -effort medium
\`\`\`
```

**If only prefix matches found**, return suggestions:

```
Command 'place' not found exactly in innovus. Did you mean:
- place_opt
- place_detail
- place_io

Use 'search EDA command innovus <exact_name>' to load full details.
```

**If no match found at all**:
```
No command matching '<command_name>' found in innovus database.
The database contains N commands. Run 'list expert topics' or check if the tool JSON has been generated by parsers/pdf_to_structured.py.
```

## Error Handling

- **JSON file not found**: `Database for '<tool_name>' not found at knowledge/processed_eda/<tool_name>.json. Run parsers/pdf_to_structured.py to generate it first.`
- **Invalid JSON**: `Database file is malformed. Re-run parsers/pdf_to_structured.py to regenerate.`
- **Empty database**: `Database for '<tool_name>' is empty. Ensure the parser ran successfully on the source Markdown.`

## Design Principle

This skill is the **online retrieval** half of the "offline parse + online retrieve" pipeline:

```
PDF → [vision model] → Markdown → [pdf_to_structured.py] → JSON → [this skill] → LLM
```

Only load the specific command entry, never the full JSON file into the LLM context.
